# 青禾 · 年级信息收集与统计系统

适合学习和本机小规模实验的完整 MVP。Next.js App Router + TypeScript + Tailwind CSS + Prisma 6 + SQLite。中文界面，支持电脑和手机布局，数据保存在本地。

## 桌面一键启动

这台电脑的桌面已创建 **“年级工具-启动”** 和 **“年级工具-停止”** 两个快捷方式，无需打开开发工具或手动输入命令。

1. 双击快捷方式，等待初始化、构建及公网连接完成，浏览器会自动打开当前网站。通常需要几十秒，首次安装可能更久。
2. 启动窗口可以最小化，但需保持运行。电脑需开机、联网且不休眠。要停用时，双击 **“年级工具-停止”**，提示停止成功后网站和公网连接都会关闭，数据仍保留。
3. 继续使用免费的临时网址，不购买域名。每次重新启动隧道后，复制浏览器地址发给同学；重复点击启动会复用现有网站，不生成新地址。

Ctrl+C 只对真正运行网站的原窗口有效；显示“网站已在运行，无需重复启动”的窗口只负责打开网页，在那里按 Ctrl+C 不会停止其他窗口或后台进程。停止快捷方式通过本机项目目录发送带本次随机运行标识的请求，由网站管理进程关闭子服务，不开放公网停止接口，也不按进程名称批量杀进程。旧停止请求不会影响下一次启动。停止后已打开的页面可能仍显示旧内容，但刷新、登录或提交将无法连接。

如果原窗口已关闭或进程意外退出，旧运行记录可能残留。停止入口会同时检查管理进程和本机 TCP 端口：两者均已关闭时清理本次旧记录并提示成功，不会仅因记录未删除而误报超时；若端口被其他服务占用或管理进程仍在，会明确提示实际状态，不强制结束其他程序。`tests/public-stop.test.ts` 的6项测试覆盖残留记录、重复停止、进程/端口仍在运行及无效记录，另已完成真实启动与停止验证。

也可直接双击项目目录里的 `一键启动.cmd`。换电脑或移动项目目录后，在新目录执行下面的命令重新创建桌面快捷方式：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\创建桌面快捷方式.ps1
```

启动脚本会保留已有账号、学生、任务及提交。桌面快捷方式直接调用 Windows PowerShell，并保留窗口显示结果，避免批处理启动失败时闪退；不会修改全局 PowerShell 执行策略。备用的 `一键启动.cmd` 使用 Windows CRLF 换行，已通过 `.gitattributes` 固定，中文 PowerShell 脚本保留 UTF-8 BOM。当前网址也保存在 `.local/public-url.txt`。已实际验证 Windows PowerShell 启动、生产构建、重复启动检测、桌面快捷方式及完整批处理入口、无效停止请求拦截、重复停止和停止后本机/公网均不可访问。

## 让校外和手机流量也能访问（公网模式）

在项目目录执行：

```powershell
.\公网启动.ps1
```

脚本依次初始化数据库、替换默认演示密码、构建生产版，启动本机 `127.0.0.1:3100` 服务并建立 Cloudflare HTTPS 隧道。在终端显示的 `https://…trycloudflare.com` 地址可以发给其他网络的同学。访问者需要用你分配的账号登录，学生/班干部的后端权限规则保持有效。

- 数据库仍保存在本机 `prisma/dev.db`。浏览器请求经过 Cloudflare 转发，不需要云数据库、路由器端口映射或关闭防火墙。
- 工具从 Cloudflare 官方发布下载，锁定 2026.10.7，执行前检查 SHA256；启动脚本面向 Windows x64。
- 所有仍使用 `Demo2026!` 的账号都会换成各自独立的随机密码，旧 Session 注销。新密码在 **`.local/公网账号密码.csv`**，可在本机用 Excel 打开，只把对应学生的账号密码私下告知本人；不要转发整个文件。
- `.local/accounts.json` 用于本机自动测试；`.local/public-url.txt` 保存当前公网地址。这些文件和隧道工具均被 Git 忽略，切勿上传密码文件。
- 再次运行不会重新修改已经替换的密码。第一次执行后，下面“测试账号”章节里的统一密码对这些账号已经失效，本地登录也需使用新密码。
- 电脑必须开机、联网，脚本进程必须保持运行。Ctrl+C 同时停止网页与隧道；关闭电脑、休眠或断网期间无法访问。
- 这是适合 MVP 体验的临时公网入口，重启隧道会改变网址，没有持续可用保证。校园网/运营商也可能限制相关连接。固定长期网址需要域名和持久 Cloudflare Tunnel 配置；本项目没有购买域名或创建云账号。
- 固定域名部署时，显式设置 `PUBLIC_ORIGIN=https://你的域名`、`PUBLIC_MODE=true`、`COOKIE_SECURE=true`。服务端只接受指定来源的写操作，不盲目信任客户端提供的转发头。

已有构建和数据库时，可直接运行 `pnpm public:start`，无须每次重新构建。源码改动后先 `pnpm build`。

公网回归测试（先启动公网服务，测试会创建并清理虚构测试任务）：

```powershell
$env:TEST_BASE_URL = (Get-Content .local/public-url.txt).Trim()
$env:TEST_ACCOUNTS_FILE = '.local/accounts.json'
pnpm test
```

当前已完成公网模式下的本机 HTTP 回归：17 项测试通过，包括代理来源校验、随机密码登录、班级隔离及 Excel 权限。实际公网连通性需以成功启动隧道后的验证为准。

官方说明：[Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。临时隧道用于测试与开发，不应当作正式长期运行方案。

## 体验流程

1. 教师登录，在“创建任务”填写名称、说明、年级、截止时间。
2. 可指定全年级；指定部分学生时，支持年级全选、班级多选和逐人勾选混合操作。它们共用同一份去重名单，班级与年级显示全选/部分选中/未选状态，批量选中后可取消个别人，取消班级只影响该班。年级全选包含仅归属年级的未分班学生，切换目标年级清空原选择；取消“仅指定学生填写”则按当前全年级发布。可设置是否允许修改、是否允许班干部查看答案。
3. 添加文本、多行文本、数字、单选、多选、日期、是/否字段，保存草稿。
4. 在任务管理发布。可以调整截止时间或手动结束。
5. 退出并以学生或班干部登录，填写与修改任务，查看自己的提交记录。
6. 班干部从“本班管理”进入统计，复制未提交名单，导出本班 Excel。即使自己不是填写对象，也能管理指定本班同学的任务。
7. 教师查看全年级统计，点击班级进度可筛选明细与统计数字，导出全年级或所选班级结果。

### 教师添加年级和班级

进入教师端“班级管理”，点击“添加年级”，填写例如“2026级”。年级创建后会自动选中，空年级也会显示“添加班级”入口。添加班级时选择所属年级并填写班级名称，成功后可立即在添加学生、转班和创建任务中选用。

年级名称不能重复；同一年级内班级名称不能重复，不同年级可以有同名班级。名称会去除两端空白，最长60字。后端使用教师权限校验和数据库唯一索引，普通学生与班干部不能调用创建接口。查看同名班级的名册时会同时限定所属年级。

教师可在年级标题旁点击“删除年级”，在班级卡片点击“删除班级”，输入完整名称确认。只能删除没有学生账号的班级，以及没有班级和任务的年级。有学生时请先转班或删除不再需要的账号；有任务时需先在任务管理中导出需要保留的结果，再删除任务。草稿、收集中和已截止任务都会阻止年级删除。

删除检查与操作在同一事务完成，不自动级联删除学生、任务或提交。学生和班干部没有删除权限，绕过页面直接请求也会被拒绝。删除成功后列表与筛选项会更新。暂不支持重命名。实现位于 `src/lib/organization.ts` 和 `src/components/organization-management.tsx`，测试位于 `tests/organization.test.ts` 和 `tests/organization-deletion.test.ts`。

### 教师添加和删除学生

教师进入“学生管理”后点击“添加学生”，填写姓名和学号，年级、班级均为选填：可暂不分配、只归属年级但暂不分班，或直接分配班级。没有年级或班级时也可添加。创建时可直接勾选“设为学生干部（部门负责人）”，无需分配年级或班级，首次改密后即可发布和管理项目、被选为共同管理人。未分班时不能设为班干部；选择班级后可勾选班干部身份，也可兼任学生干部。**学号自动作为登录账号，初始密码固定为 `123456`**，无需教师手动输入账号或密码。学号只允许1～32位字母、数字、下划线和横线，不能与现有学号或登录账号冲突。密码以 bcrypt 哈希保存。

新学生首次使用学号和 `123456` 登录时，系统显示必须完成的设置密码弹窗。新密码至少8位且包含字母和数字，bcrypt 最多72字节，需输入两次确认。设置成功后使用学生自己的密码登录，初始密码立即失效。

改密前只允许读取最小个人资料、设置新密码或退出登录；任务、答案、班级统计和导出接口均返回403。改密事务会清除所有初始密码会话并创建新的登录会话，并发旧密码登录也不会留下可用会话。**本规则适用于之后通过教师端新建的学生；已有账号、Seed账号和现有密码保持原样**。学生自设密码不会保存到演示账号 CSV 或日志中。

新增学生不自动加入已经创建的任务。只归属年级的未分班学生可参加之后创建的本年级任务；完全未分配的学生需先分配归属。添加成功后名册会切换到新学生对应的年级并显示该学生。

点击名册中的“删除账号”，输入该学生登录账号再次确认。**删除不可恢复，会删除该学生及其提交、答案、任务关联和登录 Session，相关任务统计人数会变化**；任务本身和其他学生数据保留。不能通过此入口删除教师。普通学生和班干部直接调用新增/删除接口也会收到 403。

实现位于 `src/lib/students.ts` 和 `src/components/student-management.tsx`，不需要变更数据库结构。新增集成测试 `tests/student-management.test.ts` 仅允许连接本机，测试时只创建和删除临时测试学生，不能对公网发送凭据。建议使用独立测试库，避免用户数据影响测试条件。

### Excel 批量导入学生

教师进入“学生管理”→“批量导入”，上传 `.xlsx` 文件，年级和班级均可不选：可暂不分配年级和班级、只归属年级但暂不分班，或归属具体班级。没有任何年级或班级时也能导入；预览会明确显示归属。可点击“下载 Excel 模板”；第一行必须包含“姓名”和“学号”两列，从第二行填写，每次最多200人、文件不超过1 MB。只读取第一个工作表，姓名和学号列可调换位置，其他列忽略。旧版 `.xls` 请先用 Excel/WPS 另存为 `.xlsx`。

名册显示“暂未分班”和“暂未分配”，可按分配状态筛选，再点击“分配班级”分配到目标班级；账号、密码和历史记录保留。只有年级归属的学生计入该年级人数，并可参加该年级新建的任务。完全未分配的学生暂不自动加入年级任务。未分班学生不能设为班干部；有未分班学生的年级不能删除。`User.gradeId` 仅保存未分班学生的独立年级归属，分班后清空并以班级所属年级为准，已有学生数据不变。

学号建议整列设为“文本”，尤其是有前导零或超过15位的学号。模板已预设文本格式；数字单元格仅接受不超过15位的非负整数，支持简单 `000…` 显示格式的前导零；公式、小数及包含小数点或加号的科学计数法文本会报错，不会猜测或修复学号。

点击“检查并预览”可核对姓名、学号、目标归属与逐行错误，此时不写入数据库。预览中可直接修改姓名、学号，或点击“移除本行”排除本次不需导入的学生；也可“恢复原表名单”撤销本次编辑。修改或移除后必须点击“重新检查名单”，通过后才能确认导入，导入人数随保留行数更新。移除只影响本次导入，不删除已有学生账号。

姓名允许重名；同名但学号不同的学生可独立导入，不按姓名合并或覆盖账号。空行自动忽略；必填、长度、学号格式、表内重复及已有学号/账号冲突均在后端检查。有错误时**整批拒绝，不会部分创建或覆盖原账号**。确认导入时会重新解析原始上传文件、应用逐行编辑和移除、校验归属和重复账号，并在事务中整批创建；后端不接受伪造的行号、身份或校验结果，重传同一批数据不会重复创建学生。所有编辑只在本次导入界面中保留，不改写原 Excel 文件。

新账号默认普通学生，预览表的“身份”列可逐人选择普通学生、学生干部、班干部或学生干部兼班干部。学生干部无需年级或班级；班干部及兼任身份需选择班级。身份修改后须重新检查，确认导入时后端重新验证并整批保存，更换年级或取消班级会清除班干部设置、保留学生干部设置。登录账号等于学号，初始密码 `123456`，使用独立盐的 bcrypt 哈希，首次登录必须设置个人密码。不会自动加入历史任务；也可在导入后使用“设置身份”调整。导入与模板下载都仅限教师。实现位于 `src/lib/student-import.ts`、`src/components/student-import-dialog.tsx`，测试位于 `tests/student-import.test.ts`。上传文件只在内存中处理，不保存到项目或 GitHub。

### 已有学生转班

教师在“学生管理”中点击对应学生的“转班”，选择目标年级和班级后确认。支持同年级和跨年级转班，不允许选择当前班级。默认以普通学生身份转入；只有明确勾选“转入后设为班干部”才会获得目标班级管理权限。

账号、密码、学号、历史任务填写对象和提交答案均保留，已有登录在下次请求即按新的班级/身份校验，无需重新登录。名册、班级人数、任务统计及 Excel 都按当前班级归属，不保存历史班级快照；不自动加入目标年级以前创建的任务。并发操作导致所属班级变化时，接口会要求刷新后重新操作。

后端实现 `transferStudent` 位于 `src/lib/students.ts`，页面位于 `src/components/transfer-student-dialog.tsx`；`tests/student-transfer.test.ts` 覆盖教师权限、跨班/跨年级、历史记录保留和旧 Session 权限隔离。

### 教师修改学生身份

在“学生管理”点击学生对应的“设置身份”，选择“普通学生”或“班干部”后保存，无需转班或重新创建账号。班级、学号、账号、密码和历史提交均保留。

只有教师可以操作；此入口不能修改教师身份或把学生设为教师，未分班学生需先分班再设为班干部。班干部始终为 `STUDENT`，仅更改 `isClassOfficer`。后端在每次请求重新读取身份，因此晋升后可管理本班、降为普通学生后原 Cookie 立即不能访问班级统计/答案/导出；学生刷新页面后菜单同步。

后端函数 `setStudentIdentity` 与界面 `student-identity-dialog.tsx` 实现此流程，`tests/student-identity.test.ts` 覆盖升级、降级、自行提权拦截、跨班隔离和同一 Session 的权限变化。

截止状态由服务器每次查询和提交时判断，无须定时任务。超过截止时间不可提交，手动结束不可重新发布。截止前是否能修改取决于任务设置。

教师在“任务管理”或首页任务卡片点击“删除任务”，输入完整任务名称确认后，可删除草稿、收集中或已截止任务。**删除不可恢复，会同时删除该任务的字段、填写名单、全部提交及答案**；需要保留结果时请先导出 Excel。其他任务、学生账号不会被删除。学生和班干部没有删除权限，后端也会拒绝越权请求。

### 超级管理员管理教师账号

现有站点所有者已通过迁移获得超级管理员权限，登录后进入侧栏“教师账号管理”。普通教师、班干部和学生均不能使用教师账号列表、创建、修改或删除接口。新安装演示库的初始教师由 Seed 设为管理员；现有库的演示教师不会因迁移自动提权。

创建时填写教师姓名和登录账号（3—60位字母、数字、下划线或短横线）。初始密码统一为 `123456`，每个账号使用独立盐的 bcrypt 哈希保存；和学生一样，首次登录必须设置个人密码，改密前不能访问任务、名册和统计。新教师拥有全年级教师权限，但没有超级管理员权限。已有教师和超级管理员的当前密码不会因这项规则自动重置。

教师列表的“修改信息”支持更新姓名、登录账号和重设密码。新密码留空则保持原密码，填写时至少8位；普通教师重设密码后再次登录必须设置个人密码。修改账号或密码会注销该账号的全部登录会话；超级管理员可编辑自己的账号，权限和删除保护保留，修改自己的登录信息后需重新登录。此入口不能修改学生、赋予管理员权限或编辑其他超级管理员。

删除时须输入完整登录账号确认，不能删除自己或任何超级管理员。删除后账号及其登录会话立即失效；其创建的任务移交给执行删除的管理员，任务、学生和填写结果保留。删除不可恢复。

实现位于 `src/lib/teachers.ts`、`src/components/teacher-management.tsx`，数据库迁移为 `20261124010000_teacher_admin`。`tests/teacher-management.test.ts` 和 `tests/teacher-update.test.ts` 覆盖越权与跨站拦截、参数校验、统一初始密码、初始改密、账号编辑、会话注销、受保护账号及删除后的历史数据保留。

### 文件和照片收集

创建任务时，字段类型可选“文件上传”或“照片上传”，支持必填和截止前修改。每题最多5个文件、单个不超过50 MB、整份提交附件合计不超过80 MB（包含已保留附件和签名）。“文件上传”支持 PDF、Word、Excel、PPT、TXT、CSV、ZIP 和常见图片；“照片上传”支持 JPG、PNG、GIF、WebP，服务端检查图片签名。学生可从电脑或手机选择多个文件，提交前可移除已选择文件，再选择别的文件替换；选中的文件仅在确认提交时上传并保存。保存修改时也可保留、移除或替换原附件，前提是任务仍允许修改且未截止。

字段类型还可选“手写签名”，支持必填。学生用鼠标或手指在签名板书写，提交前可“清空重写”；签名以PNG图片随提交保存，每题一份且不超过1 MB。教师可在任务统计中查看或下载签名，Excel导出包含签名下载链接；下载权限、截止、修改与删除规则和附件一致。重签后保存会替换原签名，必填签名不可直接清空后提交。

手机“文件上传”提供“选择文档 / 文件”和“选择照片 / 拍照”两个入口：通用文件入口不设置图片或扩展名过滤，也不指定相机，选择后仍由前后端检查支持格式、大小和数量。照片字段保留图片选择入口。手机系统和微信客户端最终决定原生选择菜单，网页不能强制显示文件管理器；若微信中仍只有拍照/相册，可展开“微信里只有相册，选不到文档？”按提示在手机浏览器打开，或复制网站链接再打开。聊天里的文件可先保存到手机。切换浏览器需重新登录，未提交内容不会自动迁移。

教师在任务统计明细中点击文件名下载、点击“查看照片”打开图片。Excel 导出包含文件名称和当前网址下的下载链接，访问仍需登录；临时公网网址改变后，应从当前网站重新导出。学生只能下载自己的附件；班干部只有任务允许查看答案时才能下载本班学生附件，跨班和未授权下载均被后端拒绝，身份变化即时生效。

附件二进制数据保存在 SQLite 的 `Attachment` 表中，不放入公开静态目录，也不上传 GitHub。附件与提交在同一事务中写入；提交失败、取消填写不留文件，替换或移除附件时删除旧数据，删除学生或任务时级联清理。备份 `prisma/dev.db` 会一并备份附件；文件较多时数据库会相应增大，适合现有单机小规模使用。

实现位于 `src/lib/attachments.ts`、`src/components/student-form.tsx` 和 `src/components/attachment-links.tsx`，迁移为 `20261124030000_attachments`。`tests/attachments.test.ts` 覆盖附件字段、上传校验、本人/教师/班干部下载权限、越权引用、Excel链接、截止和禁止修改、事务回滚、附件替换及删除清理。

### 上传保存性能与进度

附件读取采用限流的流式请求体，交给 multipart 解析器前不再额外拼接整份上传数据；图片类型检查直接读取现有字节视图，减少大文件复制。先完成全部字段和附件归属校验，再在同一事务中批量写入附件，失败回滚和下载权限保持有效。仅修改文字并保留附件时发送 JSON 和附件ID，不重新上传原文件。

填写页面展示真实上传百分比和已发送大小。上传100%后显示“正在确认保存”，收到服务器成功回执才更新“我的提交”；保存成功后直接利用回执更新时间，不再额外请求工作台。提交期间防止重复点击；网络失败保留填写内容和已选文件。成功响应附带 `Server-Timing` 的 `receive` 和 `save` 耗时，便于区分接收解析与数据库保存。

`scripts/benchmark-submissions.ts` 只允许本机地址与 `.local` 内独立测试库，使用虚构用户和文件，结束后清理。用同一独立库分别启动优化前后的服务，再运行脚本（优化前不带参数，优化后带 `--after`）；该参数仅控制结果标签，结果保存到 `.local/submission-benchmark-before.json` 和 `.local/submission-benchmark-after.json`，不上传 GitHub。本次每种场景3次、本机HTTP中位数如下；这些结果不代表手机公网传输速度，小请求也未呈现一致提速。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 不保留原附件，仅提交文字 | 54.0 ms | 79.9 ms |
| 单个12 MB附件 | 713.7 ms | 567.2 ms |
| 保留原附件，仅修改文字 | 36.3 ms | 43.3 ms |
| 两个6 MB附件 | 776.6 ms | 555.9 ms |

大附件样本改善约20%—28%；小请求的实际体验主要受取消额外刷新与网络延迟影响。原文件大小、手机上行带宽、网络往返、电脑负载与并发仍会影响总等待时间。

## 数据库结构

- `Grade → Class → User`：多个年级，每个年级多个班级；班干部仍是 `STUDENT`，额外设置 `isClassOfficer`。
- `User.passwordHash`：bcrypt 哈希（cost 12），没有明文密码列。
- `User.mustChangePassword`：标记首次登录是否必须设密。迁移默认为false以保留旧账号行为，教师新建学生时设为true；成功设置个人密码后变为false。
- `Session`：随机 256 位 token 放入 HttpOnly、SameSite=Lax Cookie；数据库只保存 token 的 SHA-256 摘要，7 天过期，退出立即删除。
- `CollectionTask → FormField`：任务与有序字段。选择题选项保存为 JSON 字符串。
- `TaskTarget`：发布范围的学生名单快照，任务统计分母为指定学生人数，后续新增学生不会悄悄改变任务范围。
- `Submission → SubmissionAnswer`：提交和逐字段答案，答案保存为 JSON 字符串以支持多选。每个学生每个任务最多一份提交，每份提交每字段最多一个答案。
- 修改在事务内替换答案，保留首次 `submittedAt`，更新 `updatedAt`；页面和导出展示最近提交时间。

本地数据库：`prisma/dev.db`（由 `.env` 的 `DATABASE_URL="file:./dev.db"` 指定，路径相对 Prisma Schema）。迁移文件进入 Git；数据库、Session、依赖、构建产物与 `.env` 不进入 Git。

## 权限实现

### 五级身份与学生干部（部门负责人）

| 身份 | 项目与数据权限 | 人员权限 |
| --- | --- | --- |
| 超级管理员 | 管理全部项目、统计、答案、附件和导出 | 管理学生与教师账号 |
| 教师 | 管理全部项目、统计、答案、附件和导出 | 管理学生；不能管理教师账号 |
| 学生干部 | 创建全年级或指定学生项目；管理本人创建或被指定共同管理的项目及其全部统计、答案、附件和导出 | 无人员与组织管理权限 |
| 班干部 | 本班已发布任务的提交统计；答案和附件需项目开启授权；仅导出本班 | 无人员管理权限 |
| 学生 | 填写指定给自己的已发布任务，查看本人提交，按项目设置修改本人答案 | 无人员管理权限 |

教师在“学生管理 → 设置身份”勾选“学生干部（部门负责人）”。可兼任班干部，班级权限仍按原规则单独限定。学生干部仍属于学生，可以正常填写别人发布给自己的任务；“任务管理”显示本人创建或被指定共同管理的项目，“工作台/我的提交”保留本人填写任务。

身份使用 `User.isStudentOfficer`（默认 false），不会自动提升已有账号。每次请求恢复数据库身份，取消权限后同一登录立即失去项目管理、统计、导出及他人附件访问权限。历史项目继续由教师管理，重新授权可恢复本人项目权限。转班不取消部门负责人身份，班干部身份仍由转班操作单独确认。

项目发布、结束、删除、截止时间、统计、导出及附件下载均接受教师权限，或校验学生干部身份及 `creatorId` / `TaskManager` 明确授权；创建人固定取自 Session，不接受客户端指定。学生干部只取得发布选人必需的姓名、学号和组织归属，不取得人员管理账号列表。删除学生干部账号时，创建的项目移交执行删除的教师，保留项目及其他同学提交。

创建任务时可在“共同管理人（选填）”勾选其他学生干部，可跨班选择、可多选，不选则只由创建者和教师管理。共同管理人拥有该任务与创建者相同的管理权限（包含删除任务），并可查看未发布草稿及全部结果；授权不会扩展到其他任务。其他学生干部仍只可填写指定给本人的已发布任务；兼任班干部的原有本班统计规则保持有效。共同管理名单不等于填写名单，受邀干部无需被指定填写即可管理项目。普通学生、教师账号、无效账号、重复名单和创建者本人不能作为共同管理人提交。

共同管理关系保存于 TaskManager 关联表，删除任务或共同管理人账号时自动清理关联；取消学生干部身份后，保留的关系也不会继续授予管理权限。已有任务默认为无共同管理人。当前仅在创建时选择共同管理人。

迁移：`20261125010000_student_officer`、`20261125020000_task_managers`。新增真实 HTTP 权限测试 `tests/student-officer.test.ts`，与既有回归在独立 SQLite 虚构数据库中共151项通过；ESLint、TypeScript与生产构建通过。Next.js 构建另外提示当前依赖存在已知安全漏洞，建议另行升级验证。

所有接口均在服务器验证 Session，前端导航只负责展示。

- `auth.ts/currentUser`：每次请求从数据库恢复当前用户身份，不信任请求体的 userId、role 或 classId。
- `access.ts/accessibleTask`：学生必须是指定填写对象且任务已发布；自己的提交始终按 Session userId 查询。
- `access.ts/taskReport`：普通学生直接 403；班干部 classId 固定来自 Session，指定其他班级直接 403。教师及该任务的创建干部、共同管理干部可查看全年级。
- 统计接口和 Excel 导出使用相同查询。未授权查看答案时，班干部的数据库查询不包含答案，Excel 仅包含姓名、学号、班级、提交时间。
- 写操作校验 Origin/Host；任务创建允许教师和学生干部，项目管理验证教师身份或学生干部的创建人/共同管理授权。
- 服务端校验必填项、类型、日期、选项、未知字段和长度。提交事务内重新检查截止和可修改状态，防止前端绕过。
- 登录使用通用错误提示和进程内账号限速；响应禁止缓存。SQLite 文件的本机访问权限仍由操作系统管理。

## 重复提交、校验、防刷与并发保护

### 重复提交

学生填报仍使用一人一任务一份提交的数据库唯一约束。新版页面在网络重试时复用请求标识，服务端对答案和实际附件字节计算摘要，在同一写事务中保存答案及回执；同标识同内容返回原回执，不重复新增附件或改变保存时间。同标识不同内容返回409。回执存于 SubmissionRequest，重启仍保留，新提交会清理超过7天的旧回执。创建任务和填写按钮均有同步提交锁。

新版页面同时附带原提交版本，旧页面不能覆盖其他页面刚保存的新答案，冲突返回409并提示刷新。未携带新请求头的旧客户端仍兼容，受唯一约束、任务可修改设置及事务校验保护；请求重放和旧版本检查依赖客户端提供相应请求头。该机制不合并两次主动修改。

### 表单校验

保留服务端必填、字段类型、选项、日期、未知字段及附件归属/大小/格式检查。数字字符串额外限制为100字符。所有JSON接口统一流式读取，最多256 KiB，不依赖Content-Length；拒绝超过20层嵌套或20000个节点的JSON。附件表单中的文字答案使用相同限制。JSON接收超时30秒、表格接收60秒、附件接收120秒；浏览器180秒未收到保存确认会提示重试并保留填写内容。

### 防刷

按数据库账号限流，多设备登录和伪造X-Forwarded-For不能绕过账号计数。默认每分钟：账号总请求600、写入360、填报40、导出30、导入预览/确认120、下载120。登录另按账号20次/分钟和失败10次/15分钟限制，来源登录200次/分钟、来源总请求6000次/分钟。429附Retry-After；计数容量耗尽时拒绝新请求，不清空旧计数。

新上传文件每账号320 MiB/小时、全站2 GiB/小时；下载每账号1 GiB/小时、全站8 GiB/小时。拒绝的上传重试也会消耗已接收流量配额。默认只使用账号和共享来源保护；项目公网启动器仅在本机127.0.0.1绑定并经Cloudflare隧道时开启TRUST_CLOUDFLARE_IP，使用受信任的CF-Connecting-IP区分来源。不要在允许客户端直连的部署中盲目信任代理IP头。

### 并发与部署边界

API最多同时处理64个请求，附件接收/读取共享3个并发名额。密码计算、导入和导出最多2个并行，最多排队16个；应用写事务一次执行1个，最多排队64个，等待最多10秒。拥堵或数据库忙返回503及Retry-After，不自动重复执行不确定是否提交成功的写操作。排队事务失败会回滚，释放所有名额；状态、截止时间和提交条件在写事务中重新检查。

这些是单机单进程的资源保护，计数和队列重启会清空，提交回执持久保留。不要直接启动多个Next工作进程来宣称可水平扩展。更多并发需要迁移到适合多实例的数据库、共享限流与队列、反向代理/边缘防护，再按真实附件和公网网络压测。当前仍使用本机SQLite，读写锁及磁盘吞吐是容量边界，不能承诺大规模DDoS防护。参考[SQLite并发说明](https://sqlite.org/wal.html#concurrency)。

验证：151项完整回归通过，覆盖20个同标识并发重试只保存一次、附件重传不重复、旧页面冲突、限流和队列释放。独立本机SQLite、已登录学生、3字段文字表单的50人同时提交实测：50/50成功，总耗时766毫秒，P95 730毫秒；不包含公网传输、大附件或登录密码计算，不能据此承诺线上容量。测试报告保存在本机忽略目录 .local/resilience-load-result.json。

## 第一版限制

- 学生管理支持教师新增、Excel 批量导入、删除、转班和独立修改普通学生/班干部身份；暂不支持修改姓名学号、密码重置。年级/班级支持新增、查询和删除空记录，暂不支持重命名。
- 草稿字段暂不支持保存后重新编辑或复制任务；可以删除写错的任务后重新创建。
- 教师拥有全部年级权限，暂不细分教师任教范围。
- 附件支持常用文档、图片和ZIP，暂不支持视频、音频、批量压缩下载或在线文档编辑；不支持条件跳题、短信提醒、单点登录、密码找回、审计日志或提交历史版本。
- 账号限流与并发队列保存在单进程内，重启清空；跨实例防刷、边缘DDoS保护和运维仍需独立部署。
- 默认仅绑定 127.0.0.1，本机 HTTP Cookie 不设置 Secure；不作为公开网络服务。将来使用 HTTPS 时设置 `COOKIE_SECURE=true`，并重新设计部署和安全配置。
- 小规模实验不分页；SQLite 使用本地文件，适合单机低并发。未来人员调班时，统计按当前所在班级归属。
- 刷新浏览器会回到首页；截止和新提交通知在刷新/重新进入页面后更新。
- Excel 包含未提交学生（答案空白、提交时间显示“未提交”），完成率分母只计算指定对象。没有答案权限时不导出动态答案列。

不使用 Docker、云数据库、Redis 或第三方认证。

技术选型参考：[Next.js 安装说明](https://nextjs.org/docs/app/getting-started/installation)、[Prisma 6 SQLite 文档](https://www.prisma.io/docs/orm/v6/overview/databases/sqlite)、[pnpm 构建脚本授权](https://pnpm.io/cli/approve-builds)。Prisma 固定为 6.19.0，沿用直接 SQLite 引擎以简化学习；其他依赖的实际版本由 `pnpm-lock.yaml` 锁定。
